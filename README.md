# 局域网快传（LAN Transfer）

基于 **HTML + WebRTC** 的局域网文件 / 文字传输系统。同一 Wi-Fi 或局域网下的电脑、手机用浏览器打开页面即可互发文字消息和任意大小的文件，**数据通过 WebRTC 点对点（P2P）加密直连传输，不经过服务器**。

- 无需安装任何 npm 依赖，Node.js 原生模块实现信令服务
- 自动发现在线设备，点击即连，支持多设备
- 文件分片流式传输，实时进度，接收确认，可取消 / 拒绝
- 响应式界面，针对手机浏览器（含 iOS Safari、安卓 Chrome）专门优化
- 同一局域网内无需访问互联网

## 工作原理

浏览器自身没有 UDP 广播能力，且 WebRTC 建立连接前必须交换 offer / answer / ICE 候选地址，因此系统分为两层：

```
┌──────────┐   SSE 设备发现 + offer/answer/ICE 转发    ┌──────────┐
│  设备 A   │ ───────────────────────────────────────► │  设备 B   │
│  浏览器   │              （仅建连信令）                │  浏览器   │
│          │ ◄───────────────────────────────────────► │          │
│          │     WebRTC DataChannel（DTLS/SCTP 加密）   │          │
│          │     文字消息 + 文件分片，浏览器直连         │          │
└──────────┘                                           └──────────┘
        ▲                                                    ▲
        └────────────── node server.js（信令服务）──────────────┘
```

1. **信令层（server.js）**：零第三方依赖的 Node.js HTTP 服务
   - 用 SSE（Server-Sent Events）向所有页面广播在线设备列表
   - 定向转发 WebRTC 建连信令，只传协商报文，不碰业务数据
   - 同时托管 `public/` 下的静态页面
2. **数据层（浏览器 P2P）**：连接建立后，文字和文件全部走 **RTCDataChannel** 直连。同一局域网使用 host candidate（本机网卡地址），不依赖 STUN/TURN，断网也能用。

文件传输协议：控制消息（文件请求 / 接收 / 拒绝 / 取消）走 JSON 文本帧，文件数据按 **64KB 分片**走二进制帧（9 字节头部：类型 + 传输 ID + 序号），接收端按序重组为 Blob 并校验字节数；发送端带 4MB 缓冲背压控制，传大文件不会撑爆内存。

## 环境要求

- **一台运行服务的电脑**：[Node.js](https://nodejs.org/) 16 或更高版本（推荐 18/20 LTS），Windows / macOS / Linux 均可
- **其他设备**：任意现代浏览器（电脑 Chrome / Edge / Firefox / Safari，手机系统自带浏览器即可），**无需安装 Node**
- 所有设备接入**同一个局域网 / 同一个 Wi-Fi**

检查 Node 是否安装：

```bash
node -v
```

## 快速开始

### Windows（最简单：双击启动）

双击项目目录中的 `run.bat`，看到下面的输出即表示启动成功：

```
============================================
 局域网快传已启动（信令服务 + 静态页面）
============================================
 本机访问 : http://localhost:3000
 局域网   : http://192.168.x.x:3000
 ...
```

> 启动后弹出的黑色命令行窗口不要关闭，关闭即停止服务。

### 任意平台（命令行启动）

```bash
# 进入项目目录，无需 npm install
node server.js
```

或：

```bash
npm start
```

自定义端口（默认 3000 被占用时）：

```bash
# Windows PowerShell
$env:PORT=8080; node server.js

# Windows CMD
set PORT=8080 && node server.js

# macOS / Linux
PORT=8080 node server.js
```

## 使用方法

1. 在一台电脑上启动服务（见快速开始）。
2. 启动日志和页面左侧会显示局域网访问地址，例如 `http://192.168.1.4:3000`。
3. 电脑本机用浏览器打开 `http://localhost:3000`；**手机或另一台电脑**用浏览器打开 `http://192.168.1.4:3000`（地址以实际输出为准）。
4. 在左上角"我的设备名"里给自己起个名字（会自动记住）。
5. 两侧都打开页面后，设备列表会自动出现对方，**点击设备名即发起 P2P 连接**，顶部显示"已连接 · P2P 直连中"即可开始通信。
6. 文字：底部输入框输入，**Enter 发送，Shift+Enter 换行**。
7. 文件：
   - 点左侧回形针按钮选择文件（可多选），或直接把文件**拖拽**到聊天区；截图也可直接 **Ctrl+V 粘贴**发送。
   - 接收方会先看到文件卡片，点"**接收**"才开始传输，也可以"拒绝"。
   - 传输中显示进度百分比，可随时取消；完成后点"**保存到设备**"下载。

### 手机上的操作提示

- 手机浏览器打开页面后建议用浏览器菜单"添加到主屏幕"，像 App 一样使用。
- iOS 上点"保存到设备"可能会先在新标签打开文件，再点分享按钮 → "存储到文件"即可保存。
- 页面切到后台时浏览器可能暂停连接，回到前台后会自动恢复信令；若 P2P 已断开，重新点一下设备即可重连。

## 功能说明

| 功能 | 说明 |
|---|---|
| 自动设备发现 | 基于 SSE 实时广播在线列表，上线 / 改名 / 离线自动刷新 |
| 一键 P2P 连接 | 点击设备即自动完成 WebRTC 协商，无需手动复制任何代码 |
| 文字消息 | 双向聊天、时间戳、消息气泡、未读计数；中文输入法组词期间不会误发送 |
| 文件传输 | 任意类型 / 大小文件，64KB 分片 + 背压流控，多文件自动排队 |
| 接收确认 | 文件不自动落盘，接收方确认后才开始传输 |
| 进度与取消 | 实时百分比 / 已传大小，双方均可中途取消，可拒绝接收 |
| 多种发送方式 | 文件选择器、拖拽、粘贴（剪贴板图片 / 文件） |
| 多设备会话 | 支持与多个在线设备分别建立独立连接和聊天记录 |
| 断线处理 | 信令断线自动重连；双方同时发起连接有 glare 仲裁；对端刷新页面可静默重连 |
| 移动端适配 | 单栏全屏切换、触摸尺寸、安全区（刘海屏）、软键盘视口跟随、防 iOS 输入缩放 |

## 信令接口（开发者参考）

服务器只暴露三个接口，均不承载业务数据：

| 接口 | 方法 | 作用 |
|---|---|---|
| `/api/events?id=xxx&name=xxx` | GET (SSE) | 注册设备，接收 `welcome` / `peers` / `signal` 事件；20 秒心跳保活 |
| `/api/signal` | POST | 转发信令，body：`{ from, target, type: "offer"|"answer"|"candidate", payload }` |
| `/api/config` | GET | 返回本机主机名与局域网 IPv4 列表，供页面提示访问地址 |

WebRTC 配置为 `{ iceServers: [] }`：同一局域网仅使用 host candidate，无需 STUN/TURN。

## 常见问题

### 1. 手机打不开 `http://192.168.x.x:3000`

90% 是 Windows 防火墙拦截了 Node 的入站连接，按顺序排查：

1. 确认手机和电脑连的是**同一个 Wi-Fi**（注意访客网络 / AP 隔离会阻止设备互访，需在路由器关闭"AP 隔离 / 客户端隔离"）。
2. 确认用的是启动日志里打印的**局域网 IP**，不是 `localhost`（localhost 在手机上指手机自己）。
3. Windows 首次运行若弹出防火墙提示，勾选"专用网络"并点"允许访问"。若错过了弹窗：
   - 打开"Windows 安全中心 → 防火墙和网络保护 → 高级设置 → 入站规则"，新建规则 → 端口 → TCP `3000` → 允许连接，名称随意。
   - 或临时关闭专用网络防火墙做验证（验证后建议重新开启并用端口规则放行）。
3. macOS："系统设置 → 网络 → 防火墙"中允许 node 接收入站连接。
4. 公司 / 校园网常开启客户端隔离，改用手机热点让两台设备接入即可验证。

### 2. 端口 3000 被占用

用 `PORT=8080 node server.js`（PowerShell：`$env:PORT=8080; node server.js`）换端口启动，访问地址端口同步更换。

### 3. 显示在线但点击后一直"连接中"

- 确认两端没有使用 VPN / 代理软件（可能拦截局域网直连）。
- 刷新两端页面后重新点击设备。
- 路由器若开启了"客户端隔离 / AP Isolation"，需要关闭。

### 4. iOS 收到文件后点保存没有反应

iOS Safari 对部分文件类型不会直接下载，会在新页面打开文件预览，再点底部分享按钮选择"存储到文件"。

### 5. 传输大文件时页面卡顿吗？

不会。文件使用分片读取发送（每片 64KB），发送缓冲区超过 4MB 自动背压等待，接收端用 Blob 增量合并，内存占用平稳。注意手机端长时间锁屏可能导致浏览器挂起传输，传大文件时建议保持页面在前台、屏幕常亮。

### 6. 传输安全吗？

WebRTC DataChannel 强制使用 DTLS 加密，数据只在两端浏览器之间传输，服务器（及同一局域网的其他设备）无法看到内容；服务器只转发了几百字节的建连信令。
